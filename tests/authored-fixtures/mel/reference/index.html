Build with the Ada MEL interfaces

Safe Ada interfaces for IR and RF data and control, backed by one private native C ABI and a C++ bridge to pinned, published MEL interfaces. Explicit lifetime and ownership boundaries make resource use visible to the application.

Start with the guides above, then use the package directory below or the complete native API reference. All navigation works offline without JavaScript.

Bindings, not a complete system

This library is not a complete AMS GRA Skill, MFA implementation, OMS, production service, or provider-specific implementation such as Squall. MEL bindings alone do not establish general AMS GRA compliance. Integration, service behavior, security, scheduling and hardware qualification belong to the system using the bridge.

Choose a public package

Shared/Core supplies roots, Session and common status values. IR uses Session-backed channels. RF has independent DataMEL, Admin and C2 owners. The package selection guide connects developer tasks to these separate families.

Documentation status

Public API documentation is complete under the strict source/rendered-identity model: 4,294 / 4,295 measured elements are documented, with zero public documentation gaps. The one uncredited source-visible alias, AMS.MEL.IR.Health_Status.Metadata.Status, renames AMS.MEL.Status. GNATdoc 26.0.0 does not render that package-renaming section. This is a known renderer limitation, not a missing implemented API or a provider capability. Follow AMS.MEL.Status for its target.

The native inventory remains 1,238 source declarations and 1,237 rendered sections, with one exact renderer exception. These numbers measure documentation identity, not full upstream feature support.

Provider capability and evidence

Runtime providers determine optional capabilities. Mock tests establish bridge semantics, ownership and conversion behavior, not physical RF behavior. Historical Squall results are pinned observations, not promises for other revisions or configurations. Successful submission, Job Add or Finalize calls are not automatically proof of hardware execution.
