IR Workflows

IR is Session-backed and channel-oriented. Open a Session with AMS.MEL, then configure the particular channel family. Provider library and configuration values are deployment inputs, not portable examples.

Image stream: attach, start, consume, close

AMS.MEL.IR supplies Create_UCI_ID, Create_Component_Location, Create_Image_Config, Open_Image_Stream, Start, Stop and Close. Configuration owns the identities, sensor location and positive buffer/queue bounds. Opening attaches but does not start reception.

Illustrative operation sequence, not standalone executable Ada: the caller supplies valid provider configuration, identities, mounting values, and exception handling.

Full representation is not a new format negotiation path

The legacy AMS.MEL.IR.Receive returns a source-compatible Mono8 frame subset. AMS.MEL.IR.Image provides the complete published FrameHeader representation in Full_Frame, preserving nested metadata and pixels as an independent Ada copy. Both use the current validated Mono8 single-band stream path; a complete header representation is not support for every upstream pixel format.

Acquire_Frame returns a limited Frame_Lease with small metadata copied into Ada and a retained provider payload. With_Pixels borrows only during its processor invocation; Copy_Pixels produces independent Ada storage. Do not retain a view beyond the invocation or race Close with a borrow. Lease Close invalidates the payload and resets its count; copied metadata remains. Buffer-release failure reports an error and conservatively retains uncertain storage, not successful release. Only one Receive/Acquire consumer may operate on a stream at a time.

Capabilities and commands

AMS.MEL.IR.Channel defines common identities, pixel vocabulary and complete capability snapshots. AMS.MEL.IR.Image.Capabilities and AMS.MEL.IR.C2.Common.Capabilities return Ada-owned values. An enum member such as an optional metadata kind is not evidence that its callback is implemented or that the provider supplies it.

AMS.MEL.IR.C2 owns Control_Channel: configure, Open, explicitly Enable, then submit commands such as Submit_Mode, Submit_BIT_No_Op or Submit_Config_Set. ModeCmd preserves complete ScanParam; supported BIT operations are the documented one-choice operations, not arbitrary invented payloads. AMS.MEL.IR.C2.Common provides pre-enable KeepAlive, asynchronous CommsTest and capability inspection.

Bounded metadata delivery

AMS.MEL.IR.C2.Metadata receives CommandStatus, BIT_Configuration and BIT_Status, with explicit ChannelCommsTest admission. AMS.MEL.IR.Image.Metadata receives BadPixelList, LineOfSightReport, LineOfSightEuler and NavigationReportResp. The current Image metadata does not implement LineOfSightQuaternion simply because upstream vocabulary names it. Native provider callbacks enqueue; Ada consumers use Receive in C2.Metadata, Image.Metadata, Health_Status.Metadata and Instrumentation.Metadata to obtain copied values. Track.Metadata.Receive_Event returns tagged multi-kind events; its separate Receive convenience function returns Track reports only. If that convenience function consumes a non-report event, it raises Provider_Error rather than skipping or requeuing it. Use Receive_Event for mixed Track metadata kinds. Queues are bounded, drop incoming events when full, and expose counters; they are not lossless buses.

Health, Instrumentation and Track

AMS.MEL.IR.Health_Status owns its channel and AMS.MEL.IR.Health_Status.Metadata delivers copied status metadata. Its Status alias targets AMS.MEL.Status; the known GNATdoc package-renaming omission does not mean status support is missing.

AMS.MEL.IR.Instrumentation is conditional: configure, Open, Enable, Submit, Wait and Close. AMS.MEL.IR.Instrumentation.Metadata receives InstrumentationReport. AMS.MEL.IR.Track is likewise conditional. AMS.MEL.IR.Track.Updates submits TrackDataUpdate; AMS.MEL.IR.Track.System_Data submits SystemTrackDataResponse. AMS.MEL.IR.Track.Metadata delivers IRSTTrackReport, RequestSystemTrackData, CandidateObjectMessage and CandidateObjectPreProcMessage on one FIFO queue. Those inbound callbacks have no corresponding upstream send overload. Positive Track behavior is mock-backed; the pinned Squall observation is a clean failure to attach a Track channel, not positive Track execution.

Navigation requests and lifetime

AMS.MEL.IR.Image.Submit_Navigation_Report owns the complete Navigation_Report, including all 18 covariance terms. Submission is allowed while logically Attached or Running and returns a limited Navigation_Request. Wait observes a cached terminal result. Timeout leaves the request pending; request Close abandons the public handle and is not cancellation.

Pending requests and held leases keep native provider/channel state alive independently of the public Image_Stream and Session. Parent-first logical closure is supported by retained child claims; it does not authorize new work on closed parents or promise immediate physical teardown. Metadata Close stops public consumption, not universal callback quiescence. Serialize lifecycle operations on the same owner. Read the ownership/error contracts before shutdown.

Source basis

The operation contracts are in ada/src/ams-mel-ir*.ads and ada/README.md; native behavior is in native/src/ir_stream.cpp, ir_image.cpp, ir_navigation.cpp and the corresponding channel implementations. Mock tests under ada/tests/src and native/tests establish conversions and ownership. Historical docs/task-029* reports distinguish mock-positive Track evidence from pinned-provider limitations.
