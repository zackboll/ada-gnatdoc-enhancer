Ownership and Errors

Ownership is part of the API, not an implementation detail. Use explicit Close at a deliberate boundary and retain exception handling around it. Limited controlled owners cannot be copied; default owners are closed. Automatic finalization attempts non-raising cleanup but cannot prove successful shutdown.

Parents, children and snapshots

Native child claims retain provider objects, futures and library state. Parent-first public closure is supported where documented: IR pending requests and frame leases, RF pending requests, apertures, Jobs and endpoints can retain the underlying graph. A closed parent cannot accept new operations. A future that never completes can retain its graph indefinitely. This safety behavior is not permission to unload code or assume timely resource reclamation.

Independent copied snapshots remain ordinary Ada values. Some controlled owners also retain small copied fields after Close: IR lease metadata, RF VA IDs/labels, Job details and ProductRx endpoint/event metadata have explicitly documented accessors. Payload access and live provider operations still require an open owner. Do not infer that every accessor works after Close from the fact that one cached field does. Check each precondition and index range.

Borrowing and callback boundaries

{{package:AMS.MEL.IR.Image}} With_Pixels and {{package:AMS.MEL.RF.Product_Rx}} With operations call your processor synchronously. A borrow ends on normal return or exception. Never save an address, access value, slice or view; never close the owner during that borrow. Use the explicit Copy operation when data must escape the processor scope.

Provider callback threads operate native queues; they do not invoke Ada application callbacks. Queues are bounded, with drop counters and family-specific admission rules. IR metadata queues use DROP-INCOMING. Monitor counters and do not assume notifications form a lossless or complete current-state history.

Upstream does not universally provide unregister/quiescence contracts. RF registration retains the exact callable and provider DSO permanently, including a shell after endpoint cleanup; IR callback teardown follows channel/buffer lifetime rules. Never unload a provider DSO while an object, deleter, pending future, request or unquiesced callback could execute provider code.

Timeout, rejection and exceptions

  • Timeout_Error means no result within the selected wait. It is not cancellation, rejection, or request consumption; zero timeout polls.
  • Normal result discriminators encode provider outcomes: RF Created/Failed, IR Success/Rejected, Admin Boolean acceptance, or status enums. These are not automatically bridge exceptions or proof of hardware execution.
  • Provider_Error reports native bridge/provider failures according to each operation: validation, closed handle, provider exception, malformed result, or cleanup failure. Native error categories distinguish provider exceptions from bridge/internal failures even where Ada uses one exception.

Observe the result discriminator before a preconditioned accessor. RF Error_Code/Description require Failed; IR Rejection_Code/Description require Rejected, while successful command accessors require Success. A successfully returned CommandStatus can itself report a normal Rejected state; that is distinct from an ErrorOr rejection of the bridge operation. A BIT Return Fail is likewise a normal returned value, not automatically a provider exception.

Wait, Claim, Close and cancellation are different

Native completion workers call future get once and cache terminal results. Repeated Wait reads that cache. RF resource requests require a separate unique Claim; Created alone does not transfer ownership. Claim is not repeatable, and family-specific pending/failed/registration-failure behavior must be observed.

Request Close is nonblocking abandonment, not cancellation of pending work. Closing an unclaimed successful request releases its resource through native cleanup; an already claimed child remains independent. RF Cancel_Job is an explicit separate provider operation with its own result, not an implied effect of every Close.

Cleanup failures and concurrency

Explicit Close may report failure. Some IR detach failures preserve an owner for retry; RF final-child shutdown may close the public handle and retain an uncertain graph without retry. IR buffer-release failure invalidates the borrow and conservatively retains storage. Never generalize one family's retry policy. Non-raising finalization suppresses cleanup exceptions and may deliberately retain resources rather than permit use-after-free or unsafe unload.

Externally serialize operations on the same Ada owner, especially Wait, Claim, borrow/copy, Close and finalization. Internal worker/queue synchronization does not confer general thread safety on a shared owner. IR streams allow one receive/acquire consumer; independently acquired leases have separate lifetimes.
