Architecture

One consumer-side adapter connects safe language clients to published MEL interfaces. It does not use Squall-private gRPC/UDP contracts. CMake owns native compilation; the Ada GPR project imports the native library.

The language and provider boundary

Ada application
    |
Safe Ada MEL interfaces
    |
Private Ada C imports
    |
Stable native C ABI (experimental, explicitly versioned)
    |
C++ bridge
    |
Published upstream MEL interfaces
    |
Runtime provider implementation

The C ABI intermediary prevents STL containers, C++ references, templates, exceptions and provider object layouts from crossing the language boundary. Direct C++ binding would couple clients to those compiler and layout details. The private C++20 adapter translates explicit opaque handles, fixed-width records, spans, diagnostics and timeouts. This stabilizes the language boundary; it does not eliminate provider-side C++ ABI compatibility requirements, promise unlimited ABI evolution, or make all owners concurrently usable.

Where ownership and asynchronous work live

Native state objects own provider shared resources, library handles, futures, registered buffers and child claims. Limited controlled Ada owners hold private handles. Values such as channel capabilities, full-frame copies, MFA/VA/Job snapshots and metadata events are copied into Ada-owned records and vectors. IR frame leases and RF event payloads instead expose explicitly scoped borrows or copy operations.

Native completion workers consume futures once and cache terminal results. Provider callbacks enter bounded native queues, not Ada application code. Application-side Receive operations copy metadata; explicit With operations invoke a synchronous Ada processor over a borrowed payload. Provider callback registration may require permanent retention of the exact callable and DSO. Logical closure can precede physical teardown. The ownership guide explains that distinction.

Integration scope

Squall is an example runtime provider, not this bridge's implementation. Historical tests apply only to their recorded revision and configuration. An MFA implementation may supply these MEL interfaces to a Skill integration; the application must still implement its required service, orchestration and system-level contracts. This repository is neither OMS, a complete AMS GRA Skill, nor a complete MFA. No general GRA-compliance claim follows from bindings.
