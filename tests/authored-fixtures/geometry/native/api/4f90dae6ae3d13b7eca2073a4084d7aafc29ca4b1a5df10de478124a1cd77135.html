Description

Computational geometry on Ada-owned point sets, backed by native OpenCV: contour area, length and moments; convex hulls, hull indices and convexity defects; curve approximation, convexity tests, bounding rectangles, point location and shape matching; minimum-area rectangles and enclosing circles and triangles; ellipse and line fitting; convex polygon and rotated-rectangle intersections; and affine and perspective transforms. Planar Delaunay and Voronoi subdivisions are in the child package OpenCV.Geometry.Subdiv2D.

Point sets: a Contour is an OpenCV.Point_Array of integer points, passed to OpenCV as CV_32S. Overloads that take a Float32_Point_Array use OpenCV's binary32 CV_32F path without rounding to integers. Input arrays may have any bounds and are read in index order; each declaration states the bounds of its result.

Ownership: every operation here is a function whose inputs are not modified. Results are Ada-owned values, arrays and records; none refers to native storage. The one exception is Get_Rotation_Matrix_2D, which returns an OpenCV.Core.Mat with Core's ordinary Mat ownership.

Errors: input that the binding rejects, failures reported by OpenCV and non-finite native results raise OpenCV.OpenCV_Error, as each declaration describes. Where native arithmetic or memory safety requires it, an operation checks documented limits before calling OpenCV; each declaration states its own.

Native backend and versions: on OpenCV 4 these operations call the native imgproc library, and on OpenCV 5 the native geometry library. The Ada declarations are the same on every supported release, OpenCV 4.6 and later 4.x releases and 5.x; where native results differ between releases, the declaration says so. Is_Natively_Supported reports what the linked OpenCV provides, not what this package binds: native approxPolyN and minEnclosingConvexPolygon remain unbound, as do 3-D line fitting, the raster-image modes of moments, boundingRect and matchShapes, and Float32 enclosing triangles. Image processing, including extracting contours from images, belongs to the OpenCV Imgproc binding.

Approximate_Curve

function Approximate_Curve
  (Points : Contour; Epsilon : OpenCV.Float64_Value; Closed : Boolean)
   return Contour

Approximates Points with Douglas-Peucker. Epsilon is the maximum distance between the original curve and the result and must be in the range 0.0 <= Epsilon < 1.0E30. Closed connects the last vertex to the first. The result is an Ada-owned contour. Empty input returns an empty contour. Points is unchanged. OpenCV 4.x measures each point's distance to the line through a chord, while OpenCV 5.x measures it to the chord itself, so the two can keep different vertices.

Approximate_Curve

function Approximate_Curve
  (Points  : Float32_Point_Array;
   Epsilon : OpenCV.Float64_Value;
   Closed  : Boolean) return Float32_Point_Array

Approximate_Curve of a Float32 point set, with the same Epsilon, Closed, and version semantics. The result is an Ada-owned Float32 point set of input points in input order, cyclically for a closed curve, whose start OpenCV chooses; it is zero-based, and empty input returns the null range 1 .. 0. OpenCV takes coordinate differences in binary32. If one overflowed, its distances would become NaN, and OpenCV 4.6, 4.10, and 5.0 would then drop points at any distance or, for Epsilon 0.0, read outside the curve without terminating. So the X span and the Y span of Points, computed in binary64, must each be at most Float32_Value'Last; wider sets raise OpenCV_Error. OpenCV 5.x also squares some differences in binary32, so beyond about 1.8E+19 it can keep vertices that 4.x drops. Points is unchanged.

Parameters
Points

Curve vertices in order, with any bounds; every coordinate must be finite. May be empty.

Epsilon

Approximation accuracy, the maximum distance between the curve and its approximation; 0.0 <= Epsilon < 1.0E30.

Closed

True when the curve is closed (the last vertex connects to the first).

Return Value

Points kept by OpenCV, in input order.

Raised exceptions
OpenCV_Error

An Epsilon outside its range or NaN, a NaN or infinite coordinate, an X or Y span above Float32_Value'Last, more than Integer_32'Last points, a non-finite native point, or a failure reported by OpenCV.

Bounding_Rect

function Bounding_Rect (Points : Float32_Point_Array) return OpenCV.Rect

Minimal upright integer rectangle containing a Float32 point set, as OpenCV computes it from the floors of the extreme coordinates: X = Floor (Min X), Width = Floor (Max X) - X + 1, and likewise Y and Height. Every point P therefore satisfies X <= P.X < X + Width. For integer-valued coordinates the result is the integer overload's. Empty input returns (0, 0, 0, 0). Points is unchanged.

Convex_Hull

function Convex_Hull
  (Points      : Float32_Point_Array;
   Orientation : Hull_Orientation := Counterclockwise)
   return Float32_Point_Array

Convex hull of a Float32 point set as an Ada-owned Float32 point set, zero-based like the integer result; empty input returns the null range 1 .. 0. Hull points are copies of input points, never rounded, except that OpenCV receives each -0.0 coordinate as +0.0: native convexHull compares its extreme points bitwise, so a set of equal points mixing +0.0 and -0.0 would otherwise yield an empty hull. The orientation convention is the integer overload's. OpenCV compares binary32 coordinate differences through binary64 cross products, and OpenCV 5.x first normalizes those differences to unit vectors, so nearly collinear points can be kept or dropped differently by OpenCV 4.x and 5.x. So that no difference overflows, the X span and the Y span of Points, computed in binary64, must each be at most Float32_Value'Last; wider sets raise OpenCV_Error. Points is unchanged. More than Integer_32'Last - 2 points raise OpenCV_Error because native convexHull computes total + 2 in signed int.

Parameters
Points

The point set, with any bounds; every coordinate must be finite. May be empty.

Orientation

Winding of the result, counterclockwise by default.

Return Value

The hull vertices in the requested winding.

Raised exceptions
OpenCV_Error

A NaN or infinite coordinate, too many points, an X or Y span above Float32_Value'Last, a non-finite native vertex, or a failure reported by OpenCV.

Convexity_Defects

function Convexity_Defects
  (Points : Contour; Hull : Point_Index_Array) return Convexity_Defect_Array

Convexity defects of Points relative to Hull, a sequence of indices in Points'Range such as the result of Convex_Hull_Indices. Hull must be strictly increasing or strictly decreasing; out-of-range, repeated, or otherwise non-monotonic indices raise OpenCV_Error. Hull is not checked to be the convex hull of Points: defects are measured against the edges between consecutive Hull indices, including the closing edge. Both Hull directions give the same result, ordered by OpenCV: the closing edge from the largest to the smallest Hull index first, then edges in ascending index order. Points should be a simple contour. After Hull is validated, a Points of at most three points or a Hull of fewer than three indices yields an empty result. Otherwise the X and Y spans of Points, Width and Height, must satisfy Width**2 + Height**2 <= 8_388_607**2, where 8_388_607 is Integer_32'Last / 256: OpenCV stores Depth * 256 rounded in a signed 32-bit integer, and no Depth exceeds the bounding-box diagonal. This also keeps native signed 32-bit coordinate subtraction from overflowing. Larger spans raise OpenCV_Error before native code runs. Points and Hull are unchanged.

Parameters
Points

A simple contour, with any bounds.

Hull

Strictly monotonic indices in Points'Range, normally Convex_Hull_Indices (Points).

Return Value

The defects, ordered by OpenCV, with every index in Points'Range and at most Hull'Length defects (the postcondition): zero-based, or the null range 1 .. 0 when there are none.

Raised exceptions
OpenCV_Error

A Hull index outside Points'Range, a repeated or non-monotonic Hull, spans beyond the fixed-point depth range, more than Integer_32'Last points, a native index outside Points, or a failure reported by OpenCV.

Fit_Ellipse

function Fit_Ellipse (Points : Contour) return OpenCV.Rotated_Rect

Least-squares ellipse fitted to Points by cv::fitEllipse. This is a fitted ellipse, not a minimum enclosing ellipse. The result is the rotated rectangle in which that ellipse is inscribed. As above, with perspective Transform_Point semantics: divide by every nonzero W, including negative and very small W; reject W = 0 rather than applying the native cv::perspectiveTransform epsilon policy.

Parameters
Transform

The homography; every coefficient finite, of magnitude at most 1.0E+269, checked even when Points is empty.

Points

The points to map, with any bounds; each finite.

Return Value

The mapped points at the same indices: exactly the bounds of Points (the postcondition).

Raised exceptions
OpenCV_Error

An invalid coefficient, or any point whose mapping Transform_Point would reject, including W = 0.0; no partial result is returned.
